# az-ddns

Azure Dynamic DNS — keeps Azure DNS A (and optionally CNAME / MX) records in
sync with your current public IP, powered by **Azure Functions (.NET 10)**.

---

## Quick start

### 1. Bootstrap dependencies + Azure setup

Run one script — it installs all required tools (Python 3 + pip, Azure CLI,
Docker, .NET 10 SDK) if missing, then launches `init.py` which interactively:

- Selects / creates a resource group
- Selects / creates an Azure Function App (Consumption plan — no idle charges)
- Creates a service principal with `DNS Zone Contributor`
- Lists your Azure DNS zones and lets you **select which domains to manage**
  (only zones visible to the SP are shown — no risk of adding a domain you
  don't control)
- Writes `dns.json` with a default A-record template for each selected domain
- Optionally configures Azure Cache for Redis (distributed concurrency lock)
- Writes credentials to `.env` and `az-functions/AzDdns/local.settings.json`

**Linux / macOS**
```bash
bash init.sh
```

**Windows** (PowerShell — requires [winget](https://aka.ms/getwinget))
```powershell
.\init.ps1
```

> **Direct run** (if all tools are already installed):
> ```bash
> python3 init.py
> ```

Installer output is redirected to a log file; the terminal only shows whether
each step succeeded or failed.

---

### 2. Review `dns.json`

`init.py` creates `dns.json` with a default `A @→{{IP}}` entry for every
selected domain. Edit it to add CNAME or MX records, or additional subdomains:

```json
{
    "domains": {
        "home.example.com": {
            "A":     { "@": "{{IP}}" },
            "CNAME": { "*": "{{DOMAIN}}" }
        },
        "nas.example.com": {
            "A":     { "@": "{{IP}}" }
        }
    }
}
```

**Placeholders**

| Placeholder   | Replaced with                             |
|---------------|-------------------------------------------|
| `{{IP}}`      | Current public IPv4 (detected server-side)|
| `{{DOMAIN}}`  | The domain name currently being processed |

**Supported record types:** `A`, `CNAME`, `MX`

---

### 3. Deploy / run

**Deploy to Azure** (requires [Azure Functions Core Tools v4](https://aka.ms/azfunc-install))
```bash
cd az-functions/AzDdns
func azure functionapp publish <your-function-app-name>
```

**Test locally**
```bash
# Start the function host
cd az-functions/AzDdns
func start

# In a second terminal — smoke-test the endpoints
python3 run.py --domain home.example.com
```

## API

Both endpoints require the `X-DDNS-TOKEN` header to match `DDNS_TOKEN` in
configuration.

### `POST /api/update`

Updates Azure DNS records. The IP defaults to the detected client IP if `ip`
is omitted.

**Request body:**
```json
{
    "ip": "1.2.3.4",
    "records": {
        "home.example.com": {
            "A":     { "@": "{{IP}}" },
            "CNAME": { "*": "{{DOMAIN}}" }
        }
    }
}
```

> The `records` structure is identical to `dns.json` — you can send the
> contents of your `dns.json` `domains` object directly.

**Response:** JSON with `detectedIp`, per-domain results, and a summary.

---

### `GET /api/list`

Lists live DNS records for all zones visible to the service principal.

Optional query parameter: `?domain=home.example.com` to filter to one zone.

## Configuration

### Azure credentials

| Variable                    | Required | Description                                           |
|-----------------------------|----------|-------------------------------------------------------|
| `AZURE_TENANT_ID`           | Yes      | Azure AD tenant ID                                    |
| `AZURE_CLIENT_ID`           | Yes      | Service principal application (client) ID             |
| `AZURE_SUBSCRIPTION_ID`     | Yes      | Azure subscription ID                                 |
| `AZURE_CLIENT_SECRET`       | Yes      | Service principal client secret                       |
| `DDNS_TOKEN`                | Yes      | Secret token sent in `X-DDNS-TOKEN` header            |
| `REDIS_CONNECTION_STRING`   | No       | Azure Cache for Redis — distributed concurrency lock  |
| `DNS_TTL`                   | No       | DNS record TTL in seconds (default: `3600`)           |
| `DNS_MX_PREFERENCE`         | No       | MX record preference (default: `10`)                  |
| `DDNS_CONCURRENCY_TIMEOUT_SECONDS` | No | Concurrency lock timeout (default: `30`)        |

For local development, copy
`az-functions/AzDdns/local.settings.json.example` to
`az-functions/AzDdns/local.settings.json` and fill in the values (or re-run
`init.py`, which writes this file automatically).

## Azure zone discovery

For a domain like `"home.example.com"` the Functions app lists all Azure DNS
zones visible to the service principal and picks the **longest-suffix match**.

- If `home.example.com` is its own zone — it is used directly.
- If only `example.com` exists as a zone — records are updated within it.

This is also why `init.py` only shows zones that are already in Azure DNS when
asking you to select domains — there is no risk of accidentally configuring a
domain you do not control.
